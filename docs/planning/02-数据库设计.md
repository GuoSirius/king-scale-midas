# 02 · 数据库设计

> 目标数据库：**Cloudflare D1（SQLite 方言）**，ORM：**Drizzle**
> 设计原则：为 D1 的计费模型（按扫描行数收费）优化 —— **宁可多建索引，绝不全表扫描**

---

## 一、设计总览

24 张表，分 5 个域：

```
┌─ A. 身份与权限 ──────────────────────────────────────────┐
│  users · roles · permissions · role_permissions          │
│  user_roles · user_approvals · login_attempts            │
│  audit_logs                                              │
└──────────────────────────────────────────────────────────┘
┌─ B. 基础字典（低频变更，可整体缓存到 KV）─────────────────┐
│  trade_calendar · stocks · industries                    │
│  concepts · stock_concepts                               │
└──────────────────────────────────────────────────────────┘
┌─ C. 核心业务（每日增量写入）──────────────────────────────┐
│  limit_records ★ · limit_record_reasons                  │
│  limit_record_revisions · market_daily_summary           │
│  concept_daily_stats                                     │
└──────────────────────────────────────────────────────────┘
┌─ D. 用户内容（人工产出，最有价值的部分）──────────────────┐
│  notes · watchlists · watchlist_items                    │
│  tags · entity_tags                                      │
└──────────────────────────────────────────────────────────┘
┌─ E. 系统运维 ────────────────────────────────────────────┐
│  ingest_jobs · settings · notifications                  │
└──────────────────────────────────────────────────────────┘
```

### SQLite / D1 的几条铁律（先记住，后面的设计都源于此）

1. **没有 BOOLEAN** → 用 `INTEGER` 存 0/1
2. **没有 DATE/DATETIME** → 交易日用 `TEXT 'YYYY-MM-DD'`（可直接 `BETWEEN` 和排序），时间戳用 `INTEGER`（Unix 秒）
3. **没有原生 ENUM** → `TEXT` + `CHECK` 约束
4. **没有真正的 ALTER COLUMN** → 表结构要一次想清楚，改列要重建表
5. **D1 按「扫描行数」计费** → 任何 `WHERE` 条件涉及的列，都要有索引；避免 `SELECT *` 大表
6. **单库上限 10GB** → 本项目每年约 15MB，无压力

## 二、A 域：身份与权限

### A1. `users` 用户表

```sql
CREATE TABLE users (
  id              TEXT PRIMARY KEY,              -- nanoid(21)
  username        TEXT NOT NULL UNIQUE,          -- 登录名
  email           TEXT NOT NULL UNIQUE,
  phone           TEXT UNIQUE,
  password_hash   TEXT NOT NULL,                 -- PBKDF2-SHA256, 格式: alg$iter$salt$hash
  nickname        TEXT,
  avatar_url      TEXT,

  -- 审核状态机：pending → active / rejected；active ⇄ suspended
  status          TEXT NOT NULL DEFAULT 'pending'
                  CHECK (status IN ('pending','active','rejected','suspended','disabled')),
  reject_reason   TEXT,                          -- 拒绝原因（展示给用户）
  apply_note      TEXT,                          -- 注册时用户填的申请说明

  -- 安全
  failed_attempts INTEGER NOT NULL DEFAULT 0,
  locked_until    INTEGER,                       -- Unix 秒，锁定到期时间
  last_login_at   INTEGER,
  last_login_ip   TEXT,
  password_changed_at INTEGER,

  -- 偏好
  theme           TEXT DEFAULT 'system' CHECK (theme IN ('light','dark','system')),
  settings_json   TEXT DEFAULT '{}',             -- 列显隐、默认筛选等个性化配置

  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  deleted_at      INTEGER                        -- 软删除
);

CREATE INDEX idx_users_status      ON users(status);            -- 管理员查待审列表
CREATE INDEX idx_users_created     ON users(created_at DESC);
CREATE UNIQUE INDEX idx_users_email_live ON users(email) WHERE deleted_at IS NULL;
```

> **注意 `password_hash` 的格式**：`pbkdf2-sha256$210000$<base64 salt>$<base64 hash>`
> 把算法和迭代次数写进字段，将来升级算法（比如迁到 Node 后换 argon2id）可以在用户下次登录时惰性 rehash，无需强制重置密码。

### A2. `roles` / `permissions` / 关联表

```sql
CREATE TABLE roles (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  code        TEXT NOT NULL UNIQUE,      -- super_admin / admin / editor / member / guest
  name        TEXT NOT NULL,             -- 显示名
  description TEXT,
  level       INTEGER NOT NULL DEFAULT 0,-- 数值越大权限越高，用于「不能操作同级或更高级用户」
  is_system   INTEGER NOT NULL DEFAULT 0,-- 系统内置角色不可删除
  created_at  INTEGER NOT NULL
);

CREATE TABLE permissions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  code        TEXT NOT NULL UNIQUE,      -- record:edit / user:approve / data:export ...
  resource    TEXT NOT NULL,             -- record / user / note / system
  action      TEXT NOT NULL,             -- view / create / edit / delete / approve / export
  name        TEXT NOT NULL,
  created_at  INTEGER NOT NULL
);

CREATE TABLE role_permissions (
  role_id       INTEGER NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
  permission_id INTEGER NOT NULL REFERENCES permissions(id) ON DELETE CASCADE,
  PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE user_roles (
  user_id    TEXT    NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role_id    INTEGER NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
  granted_by TEXT REFERENCES users(id),
  granted_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, role_id)
);
CREATE INDEX idx_user_roles_role ON user_roles(role_id);
```

**性能技巧**：用户的权限点集合在登录时算一次，写进 sealed session cookie（或 KV，key = `perm:{userId}`，TTL 10 分钟）。每次请求不查库，避免 3 表 JOIN 的行扫描开销。角色变更时主动清 KV。

## 三、B 域：基础字典

### B1. `trade_calendar` 交易日历

```sql
CREATE TABLE trade_calendar (
  trade_date   TEXT PRIMARY KEY,          -- 'YYYY-MM-DD'
  is_open      INTEGER NOT NULL,          -- 1=交易日 0=休市
  week_day     INTEGER NOT NULL,          -- 1..7
  prev_date    TEXT,                      -- 上一交易日（前端「上一日」跳转，避免递归查询）
  next_date    TEXT,
  is_month_end INTEGER NOT NULL DEFAULT 0,
  is_week_end  INTEGER NOT NULL DEFAULT 0,
  remark       TEXT                       -- 节假日名称
);
CREATE INDEX idx_calendar_open ON trade_calendar(is_open, trade_date DESC);
```
> 每年初用 AKShare `tool_trade_date_hist_sina()` 灌一次，全量约 250 行/年。
> **`prev_date`/`next_date` 冗余存储很关键** —— 前端翻页时一次查询就能拿到，不用做「找上一个 is_open=1 的日期」这种昂贵扫描。

### B2. `stocks` 股票主表

```sql
CREATE TABLE stocks (
  code          TEXT PRIMARY KEY,         -- '600519'（不带市场前缀，统一 6 位）
  market        TEXT NOT NULL CHECK (market IN ('SH','SZ','BJ')),
  full_code     TEXT NOT NULL UNIQUE,     -- 'sh600519'，对接接口时用
  name          TEXT NOT NULL,            -- 当前名称
  pinyin        TEXT,                     -- 'GZMT'，用于搜索
  board         TEXT NOT NULL             -- 板块类型，决定涨跌幅限制
                CHECK (board IN ('main','gem','star','bse','neeq')),
  limit_pct     REAL NOT NULL DEFAULT 10, -- 10 / 20 / 30，ST 为 5
  is_st         INTEGER NOT NULL DEFAULT 0,
  industry_code TEXT REFERENCES industries(code),
  list_date     TEXT,
  delist_date   TEXT,
  status        TEXT NOT NULL DEFAULT 'listed'
                CHECK (status IN ('listed','suspended','delisted')),
  total_share   REAL,                     -- 总股本（万股）
  float_share   REAL,
  updated_at    INTEGER NOT NULL
);
CREATE INDEX idx_stocks_name     ON stocks(name);
CREATE INDEX idx_stocks_pinyin   ON stocks(pinyin);
CREATE INDEX idx_stocks_industry ON stocks(industry_code);
CREATE INDEX idx_stocks_status   ON stocks(status);
```

> `board` + `limit_pct` 很重要：主板 10%、创业板/科创板 20%、北交所 30%、ST 股 5%。
> **判断「是否涨停」必须按各自的限制算**，写死 10% 会漏掉一大半。

### B4. `concepts` 概念/题材板块

```sql
CREATE TABLE concepts (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  code         TEXT UNIQUE,               -- 数据源的板块代码，可空（自定义题材没有）
  name         TEXT NOT NULL UNIQUE,      -- 'AI算力' '固态电池'
  alias_json   TEXT DEFAULT '[]',         -- 别名数组，用于原因文本归一化：["算力","AI算力","智算中心"]
  category     TEXT CHECK (category IN ('industry','concept','region','style','custom')),
  source       TEXT DEFAULT 'em' CHECK (source IN ('em','ths','kpl','manual')),
  heat_score   REAL DEFAULT 0,            -- 近期热度（定时任务算）
  is_active    INTEGER NOT NULL DEFAULT 1,
  first_seen   TEXT,                      -- 首次出现的交易日
  last_seen    TEXT,                      -- 最近一次有涨停股的交易日
  description  TEXT,
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);
CREATE INDEX idx_concepts_category ON concepts(category, is_active);
CREATE INDEX idx_concepts_lastseen ON concepts(last_seen DESC);
```

> **`alias_json` 是这张表的灵魂**。不同数据源对同一个题材叫法不一（"AI算力"/"算力租赁"/"智算"），
> 采集时先做别名归一化，否则你的题材统计会碎成一地。

## 四、C 域：核心业务 ★

### C1. `limit_records` 涨跌停记录主表（全系统最重要的表）

```sql
CREATE TABLE limit_records (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,

  -- ── 业务主键三元组 ──────────────────────────────
  trade_date     TEXT NOT NULL,                     -- 'YYYY-MM-DD'
  stock_code     TEXT NOT NULL REFERENCES stocks(code),
  limit_type     TEXT NOT NULL
                 CHECK (limit_type IN ('up','down','broken','strong')),
                 -- up=涨停 down=跌停 broken=炸板 strong=强势股池

  -- ── 冗余快照（当日名称/行业可能变，必须快照，不能只靠 JOIN）──
  stock_name     TEXT NOT NULL,
  industry_code  TEXT,
  industry_name  TEXT,

  -- ── 行情 ────────────────────────────────────────
  close_price    REAL,          -- 收盘价
  change_pct     REAL,          -- 涨跌幅 %
  amount         REAL,          -- 成交额（元）
  turnover_rate  REAL,          -- 换手率 %
  float_mv       REAL,          -- 流通市值（元）
  total_mv       REAL,          -- 总市值（元）

  -- ── 涨停特征（打板核心指标）──────────────────────
  seal_amount    REAL,          -- 封板资金（元）
  seal_ratio     REAL,          -- 封成比 = 封单额 / 成交额
  first_seal_at  TEXT,          -- 首次封板时间 'HH:MM:SS'
  last_seal_at   TEXT,          -- 最后封板时间
  open_times     INTEGER DEFAULT 0,   -- 炸板次数
  board_count    INTEGER DEFAULT 1,   -- 连板数：1=首板 2=二板 ...
  limit_stat     TEXT,          -- 涨停统计 '3/5'（5 天 3 板）
  is_one_word    INTEGER DEFAULT 0,   -- 一字板
  is_t_word      INTEGER DEFAULT 0,   -- T 字板
  limit_pct      REAL,          -- 当日适用的涨跌幅限制（10/20/30/5）

  -- ── 涨停原因（机器 + 人工双轨）★核心设计★ ────────
  reason_raw      TEXT,         -- 采集器抓到的原始原因
  reason_final    TEXT,         -- 人工校订后的最终原因（展示用，优先取这个）
  reason_source   TEXT CHECK (reason_source IN ('wencai','kpl','em','cls','manual','none')),
  is_verified     INTEGER NOT NULL DEFAULT 0,   -- 1=人工确认过，采集器不得覆盖
  verified_by     TEXT REFERENCES users(id),
  verified_at     INTEGER,

  -- ── 人工标注 ────────────────────────────────────
  is_leader      INTEGER DEFAULT 0,   -- 是否板块龙头
  rank_in_sector INTEGER,             -- 板块内排位
  quality_score  INTEGER,             -- 1-5 星，主观质量分
  remark         TEXT,                -- 备注

  -- ── 数据溯源 ────────────────────────────────────
  source         TEXT NOT NULL DEFAULT 'akshare',
  source_batch   TEXT,                -- 关联 ingest_jobs.batch_id
  raw_json       TEXT,                -- 原始行 JSON（调试/回溯用，可选存 R2）
  is_manual      INTEGER NOT NULL DEFAULT 0,   -- 1=完全手工新增的记录
  created_by     TEXT REFERENCES users(id),

  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,

  UNIQUE (trade_date, stock_code, limit_type)   -- ★幂等写入的基石★
);

-- 索引（按实际查询场景设计，D1 按扫描行数计费，这些索引必须有）
CREATE INDEX idx_lr_date_type   ON limit_records(trade_date DESC, limit_type);          -- 某日涨停列表（最高频）
CREATE INDEX idx_lr_stock_date  ON limit_records(stock_code, trade_date DESC);          -- 个股历史涨停
CREATE INDEX idx_lr_date_board  ON limit_records(trade_date, board_count DESC);         -- 连板天梯
CREATE INDEX idx_lr_industry    ON limit_records(trade_date, industry_code);            -- 按行业聚合
CREATE INDEX idx_lr_unverified  ON limit_records(is_verified, trade_date DESC)
                                 WHERE is_verified = 0;                                  -- 待校订工作台
CREATE INDEX idx_lr_leader      ON limit_records(trade_date, is_leader) WHERE is_leader = 1;
```

**几个关键设计说明：**

| 设计 | 为什么 |
|---|---|
| `UNIQUE(trade_date, stock_code, limit_type)` | 采集器可以无脑重跑，`ON CONFLICT DO UPDATE` 保证幂等。这是整个数据管道能安心重试的前提 |
| `stock_name` / `industry_name` 冗余 | 股票会改名（\*ST → 摘帽），行业会调整。历史记录必须保留**当时**的名称，否则回看 2023 年的复盘会看到 2026 年的名字 |
| `reason_raw` + `reason_final` 分离 | 机器抓的原始值永不丢失，人工改的另存一份。数据源改版时可以对比、可以重放 |
| `is_verified` 保护位 | `UPDATE ... WHERE is_verified = 0` —— 你手工校订过的数据，采集器永远碰不到 |
| `board_count` 单列 | 连板天梯是最高频查询之一，独立成列 + 索引，不要每次从 `limit_stat` 字符串解析 |
| `limit_pct` 快照 | 涨跌幅限制会变（ST 摘帽、板块调整），记录当日实际值 |

### C2. `limit_record_reasons` 记录 ↔ 题材（多对多）

一只股票的涨停原因常常是多个题材叠加（"算力 + 华为 + 数据要素"），必须拆开存才能做题材统计。

```sql
CREATE TABLE limit_record_reasons (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  record_id  INTEGER NOT NULL REFERENCES limit_records(id) ON DELETE CASCADE,
  concept_id INTEGER REFERENCES concepts(id),
  raw_text   TEXT NOT NULL,           -- 归一化前的原文，如 "算力租赁"
  is_primary INTEGER NOT NULL DEFAULT 0,  -- 主要原因（一条记录只能有一个）
  confidence REAL DEFAULT 1,          -- 归因置信度（自动匹配时 < 1）
  source     TEXT NOT NULL DEFAULT 'auto' CHECK (source IN ('auto','manual')),
  created_at INTEGER NOT NULL,
  UNIQUE (record_id, concept_id)
);
CREATE INDEX idx_lrr_concept ON limit_record_reasons(concept_id);
CREATE INDEX idx_lrr_record  ON limit_record_reasons(record_id);
```

### C4. `market_daily_summary` 每日市场情绪（复盘最常看的一屏）

```sql
CREATE TABLE market_daily_summary (
  trade_date       TEXT PRIMARY KEY,

  -- 涨跌停统计
  up_limit_count   INTEGER NOT NULL DEFAULT 0,   -- 涨停家数
  down_limit_count INTEGER NOT NULL DEFAULT 0,
  broken_count     INTEGER NOT NULL DEFAULT 0,   -- 炸板家数
  seal_rate        REAL,                         -- 封板率 = 涨停/(涨停+炸板)
  max_board        INTEGER,                      -- 最高连板高度
  max_board_stocks TEXT,                         -- 最高板股票 JSON 数组

  -- 连板结构（打板情绪的核心）
  board_1_count    INTEGER DEFAULT 0,            -- 首板家数
  board_2_count    INTEGER DEFAULT 0,
  board_3_count    INTEGER DEFAULT 0,
  board_4plus_count INTEGER DEFAULT 0,

  -- 赚钱效应
  promotion_rate   REAL,       -- 晋级率 = 今日连板数 / 昨日涨停数
  yest_limit_avg_pct REAL,     -- 昨日涨停股今日平均涨幅（最重要的情绪指标）
  yest_limit_up_ratio REAL,    -- 昨日涨停股今日红盘比例

  -- 市场广度
  rise_count       INTEGER,
  fall_count       INTEGER,
  flat_count       INTEGER,
  total_amount     REAL,       -- 两市成交额（元）
  north_net_flow   REAL,       -- 北向净流入（元）

  -- 指数
  sh_index_close   REAL,
  sh_index_pct     REAL,
  sz_index_pct     REAL,
  gem_index_pct    REAL,

  -- 情绪周期标注（人工）
  cycle_phase      TEXT CHECK (cycle_phase IN ('start','rise','peak','decline','ice','recover')),
  sentiment_score  INTEGER,    -- 1-100 综合情绪分
  editor_comment   TEXT,       -- 当日复盘一句话总结

  updated_at       INTEGER NOT NULL
);
```

> 这张表是每日首页的数据源。**它是从 `limit_records` 聚合出来的派生表** —— 采集完成后由一个后处理任务算好写入，
> 避免每次访问首页都对主表做 COUNT/GROUP BY（那会疯狂消耗 D1 的 rows read 额度）。

### C5. `concept_daily_stats` 题材每日统计

```sql
CREATE TABLE concept_daily_stats (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  trade_date      TEXT NOT NULL,
  concept_id      INTEGER NOT NULL REFERENCES concepts(id),
  limit_up_count  INTEGER NOT NULL DEFAULT 0,   -- 该题材当日涨停家数
  total_count     INTEGER,                      -- 成分股总数
  avg_change_pct  REAL,
  leader_code     TEXT,                         -- 龙头股代码
  leader_board    INTEGER,                      -- 龙头连板数
  continuity_days INTEGER DEFAULT 1,            -- 题材连续活跃天数
  rank            INTEGER,                      -- 当日题材热度排名
  created_at      INTEGER NOT NULL,
```

## 七、典型查询与性能预算

D1 按「扫描行数」计费，免费额度每天 500 万行读。下面是主要页面的开销预估：

| 场景 | SQL 要点 | 走的索引 | 扫描行数 |
|---|---|---|---|
| 某日涨停列表 | `WHERE trade_date=? AND limit_type='up' ORDER BY board_count DESC` | `idx_lr_date_type` | ~150 |
| 连板天梯 | 同上 + `GROUP BY board_count` | `idx_lr_date_board` | ~150 |
| 首页情绪面板 | `SELECT * FROM market_daily_summary WHERE trade_date=?` | 主键 | **1** ⭐ |
| 题材热度榜 | `WHERE trade_date=? ORDER BY limit_up_count DESC LIMIT 20` | `idx_cds_date` | ~80 |
| 个股涨停史 | `WHERE stock_code=? ORDER BY trade_date DESC LIMIT 50` | `idx_lr_stock_date` | ~50 |
| 近 30 日情绪曲线 | `WHERE trade_date BETWEEN ? AND ?` | 主键范围 | 30 |
| 待校订工作台 | `WHERE is_verified=0 AND trade_date=?` | 部分索引 | ~100 |

**结论**：单次页面访问约 200–400 行读。免费额度 500 万行/天 ≈ **每天 1.5 万次页面访问**。个人/小团队用绰绰有余。

真正会爆额度的是这两种写法，**务必避免**：
- ❌ `SELECT COUNT(*) FROM limit_records` —— 全表扫描，一次几万行
- ❌ 首页实时 `GROUP BY` 聚合 —— 所以我们才有 `market_daily_summary` 派生表

## 八、Drizzle Schema 示例（主表节选）

```ts
// server/database/schema/limit-records.ts
import { sqliteTable, text, integer, real, uniqueIndex, index } from 'drizzle-orm/sqlite-core'
import { sql } from 'drizzle-orm'

export const limitRecords = sqliteTable('limit_records', {
  id:            integer('id').primaryKey({ autoIncrement: true }),
  tradeDate:     text('trade_date').notNull(),
  stockCode:     text('stock_code').notNull(),
  limitType:     text('limit_type', { enum: ['up', 'down', 'broken', 'strong'] }).notNull(),

  stockName:     text('stock_name').notNull(),
  industryCode:  text('industry_code'),
  industryName:  text('industry_name'),

  closePrice:    real('close_price'),
  changePct:     real('change_pct'),
  amount:        real('amount'),
  turnoverRate:  real('turnover_rate'),
  floatMv:       real('float_mv'),
  totalMv:       real('total_mv'),

  sealAmount:    real('seal_amount'),
  sealRatio:     real('seal_ratio'),
  firstSealAt:   text('first_seal_at'),
  lastSealAt:    text('last_seal_at'),
  openTimes:     integer('open_times').default(0),
  boardCount:    integer('board_count').default(1),
  limitStat:     text('limit_stat'),
  isOneWord:     integer('is_one_word', { mode: 'boolean' }).default(false),
  limitPct:      real('limit_pct'),

  reasonRaw:     text('reason_raw'),
  reasonFinal:   text('reason_final'),
  reasonSource:  text('reason_source'),
  isVerified:    integer('is_verified', { mode: 'boolean' }).notNull().default(false),

  source:        text('source').notNull().default('akshare'),
  sourceBatch:   text('source_batch'),
  isManual:      integer('is_manual', { mode: 'boolean' }).notNull().default(false),
  createdBy:     text('created_by'),

  createdAt:     integer('created_at').notNull().default(sql`(unixepoch())`),
  updatedAt:     integer('updated_at').notNull().default(sql`(unixepoch())`),
}, t => [
  uniqueIndex('uq_lr_date_stock_type').on(t.tradeDate, t.stockCode, t.limitType),

])
```

```ts
await db.insert(limitRecords)
  .values(rows)
  .onConflictDoUpdate({
    target: [limitRecords.tradeDate, limitRecords.stockCode, limitRecords.limitType],
    set: {
      closePrice: sql`excluded.close_price`,
      sealAmount: sql`excluded.seal_amount`,
      boardCount: sql`excluded.board_count`,

    },
    where: sql`${limitRecords.isVerified} = 0`,   // ★ 已人工校订的记录，机器不许覆盖
  })
```

| 未来需求 | 预留方式 |
