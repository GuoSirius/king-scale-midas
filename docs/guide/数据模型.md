# 数据模型（金鳞·点石）

> 本文是 **当前生效** 的数据模型权威说明，覆盖 2026-08 扩展后的完整 schema。
> 早期设计稿见 `docs/planning/02-数据库设计.md`，以本文为准。
>
> 数据层：Cloudflare D1（SQLite）。本地开发用 `node:sqlite` 兼容层（`server/local/d1-shim.mjs`）镜像同一套表结构，演示数据由 `scripts/seed-demo.mjs` 直写。

---

## 1. 设计原则

1. **采集幂等**：核心表唯一键 `UNIQUE(trade_date, stock_code, limit_type)`，采集脚本可无脑重跑，不重复。
2. **冗余快照**：`stock_name` / `industry` / `sector` 等必须冗余入表，股票会改名、行业会调整，历史记录不可失真。
3. **人肉优先**：`limit_records.is_verified = 1` 的记录，采集器与种子脚本都**不可覆盖**（登陆 `reason_final` 受保护）。
4. **派生表加速**：首页情绪、板块/行业榜直接用 `market_daily_summary` / `sector_daily_stats`，避免对主表实时 `GROUP BY`（D1 按扫描行数计费）。
5. **涨跌停幅度按板块分别计**：主板 10% / 双创 20% / 北交所 30% / ST 5%（见 `boards` 字典表）。

| 表 | 域 | 用途 |
|---|---|---|
| `limit_records` | 涨跌停核心 | 每日每只涨跌停票一条记录（含全部分析维度字段） |

| `market_index_daily` | 大盘 | 上证/深成/创业板三大指数日线（与大盘对比） |
| `sector_daily_stats` | 板块 | 板块每日表现（板块榜） |

## 3. 重点表字段详解

### 3.1 `limit_records` —— 涨跌停核心（分析主表）

每日每只票的涨跌停记录。**唯一键** `UNIQUE(trade_date, stock_code, limit_type)`。

| 字段 | 类型 | 说明 | 对应分析维度 |
|---|---|---|---|
| `trade_date` | text | 交易日 `YYYY-MM-DD` | 时间轴 / 年度·同月分组 |
| `stock_code` / `stock_name` | text | 代码 / 名称（冗余快照） | 个股检索 |
| `board` | text | 上市板块 `main/cyb/star/bse` | 按板块筛选 |
| `limit_type` | text | `up` 涨停 / `down` 跌停 | 涨跌分类 |
| `price` / `pct` | real | 收盘价 / 涨跌幅% | 幅度 |
| `first_limit_time` / `last_limit_time` | text | 首次/最后封板 `HH:MM:SS` | 封板节奏 |
| `open_times` | int | 炸板次数 | 封板质量 |
| `open_time` | text | 开板/炸板时刻；封死为 `NULL` | **炸板时间分析** |
| `turnover` / `volume` / `circ_market_cap` / `total_market_cap` | real/int | 成交额/量/流通·总市值 | 体量分层 |
| `zt_count` | int | 连板数（1=首板） | **连板数分布柱状图** |
| `sector` | text | 所属板块（快照，如 新能源车） | **板块柱状图** |
| `industry` | text | 所属行业（快照，如 半导体） | **行业柱状图** |
| `pattern_days` | int | 「几天几版」天数（如 5天4版 → 5） | **几天几版** |
| `pattern_boards` | int | 「几天几版」版数（如 5天4版 → 4） | **几天几版** |
| `next_open_prediction` | text | 预测次日开盘预期（用户/模型标注） | **预测 vs 实际校验** |
| `next_open_actual` | real | 次日实际开盘涨跌幅%（T+1 回填） | **预测 vs 实际校验** |
| `reason_raw` | text | 机器抓取原因 | 原因词云 |
| `reason_final` | text | 人工最终原因（受 `is_verified` 保护） | 原因词云（优先） |
| `is_verified` | bool | 是否已人工校订（1 不可被覆盖） | 数据可信度 |
| `source` | text | 数据来源 key（如 `seed-demo`） | 溯源 |

> 原因展示规则：`COALESCE(reason_final, reason_raw)` —— 有人工结论优先用人家的。

### 3.2 `dragon_tiger` —— 龙虎榜席位

上榜票的买卖席位。**索引**：`limit_record_id` / `stock_code` / `trade_date`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` / `stock_code` | text | 交易日 / 代码 |
| `limit_record_id` | int | 关联 `limit_records.id`（级联删除） |
| `seat_name` | text | 席位名称（如 东方财富拉萨团结路 / 机构专用） |
| `seat_type` | text | `buy` / `sell` |
| `rank` | int | 1~5 上榜位次 |
| `buy_amount` / `sell_amount` / `net_amount` | real | 买入 / 卖出 / 净买额（元） |

> 分析：`GROUP BY seat_name` 汇总净买额 → **席位赚钱效应榜**；按 `stock_code` 看单票席位结构。

### 3.3 `limit_related` —— 关联票

票与票的关系网络。**索引**：`limit_record_id` / `stock_code` / `related_code`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` / `stock_code` | text | 本票交易日 / 代码 |
| `limit_record_id` | int | 关联 `limit_records.id` |
| `related_code` / `related_name` | text | 关联票代码 / 名称 |
| `relation_type` | text | `concept` 同题材 / `same_board` 同板块 / `leader` 龙头 / `follower` 跟风 / `user` 用户标注 |
| `weight` | real | 关联强度 |

> 查询为**双向**：`WHERE stock_code = ? OR related_code = ?`，可画关联图。

### 3.4 `market_index_daily` —— 大盘指数日线

三大指数日线，用于「与大盘对比」。**唯一键** `UNIQUE(trade_date, index_code)`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `index_code` | text | `sh000001` 上证 / `sz399001` 深成 / `cyb399006` 创业板 |
| `index_name` | text | 指数名称 |
| `open`/`high`/`low`/`close`/`pre_close` | real | OHLC |
| `pct` | real | 涨跌幅% |
| `volume` / `amount` | real | 成交量 / 额 |

### 3.5 `market_daily_summary` —— 每日情绪汇总（趋势图数据源）

**主键** `trade_date`。首页与折线趋势图直接读，不实时聚合主表。

| 字段 | 类型 | 说明 | 趋势图用途 |
|---|---|---|---|
| `limit_up_count` | int | 涨停数 | 折线主值 |
| `limit_down_count` | int | 跌停数 | 折线主值 |
| `limit_up_open_count` | int | 涨停打开数 | 封板质量 |
| `zt_height` | int | 最高连板高度 | 高度线 |
| `first_board_count` | int | 首板数 | 赚钱效应 |
| `seal_rate` | real | 封板率 | 情绪强度 |
| `avg_pct` | real | 平均涨跌幅 | 整体强度 |

> 按 `substr(trade_date,1,4)` → **年度**；`substr(...,1,6)` → **月度（同月/同期）**；原值 → **日**。

### 3.6 `sector_daily_stats` / `industry_daily_stats` —— 板块/行业榜

**唯一键** `UNIQUE(trade_date, sector_id|industry_id)`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` | text | 交易日 |
| `sector_id` / `industry_id` | text | 板块 / 行业名（与 `limit_records.sector/industry` 同源） |
| `limit_up_count` | int | 当日该板块/行业涨停数 |
| `avg_pct` | real | 平均涨跌幅 |
| `rank` | int | 当日排名 |

## 4. 索引与查询加速

| 表 | 关键索引 | 加速的查询 |
|---|---|---|
| `limit_records` | `lr_uniq(trade_date,stock_code,limit_type)` | 幂等 upsert |
| | `lr_date_idx` / `lr_code_idx` / `lr_board_idx` / `lr_type_idx` / `lr_zt_idx` / `lr_sector_idx` / `lr_industry_idx` | 时间/个股/板块/类型/连板/板块行业多维过滤与分组 |
| `dragon_tiger` | `dt_rec_idx` / `dt_code_idx` / `dt_date_idx` | 按记录/票/日期查席位 |
| `limit_related` | `lr_rel_rec_idx` / `lr_rel_code_idx` / `lr_rel_related_idx` | 双向关联查询 |
| `market_index_daily` | `mid_uniq(trade_date,index_code)` | 大盘对比按日对齐 |
| `market_daily_summary` | `trade_date` PK | 趋势按日/月/年聚合 |
| `sector/industry_daily_stats` | `sds_uniq` / `ids_uniq(trade_date, id)` | 板块/行业榜 |

## 5. 分析维度 → 字段映射（核心）

用户要做的大量可视化/对比，逐维对应如下：

| 分析诉求 | 数据源 / 字段 | 接口 |
|---|---|---|
| 板块涨跌停柱状图 | `limit_records.sector` + `sector_daily_stats` | `GET /api/analytics/group?dim=sector` |
| 行业涨跌停柱状图 | `limit_records.industry` + `industry_daily_stats` | `GET /api/analytics/group?dim=industry` |
| 按上市板块分布 | `limit_records.board`（`BOARD_LABELS` 出中文） | `GET /api/analytics/group?dim=board` |
| 连板数分布 | `limit_records.zt_count` | `GET /api/analytics/group?dim=ztCount` |
| 涨停原因词云/柱状 | `COALESCE(reason_final, reason_raw)` | `GET /api/analytics/group?dim=reason` |
| 几天几版 | `pattern_days` / `pattern_boards` | 前端组合展示 |
| 炸板/开板时间 | `open_time` / `open_times` | 前端筛选 |
| 龙虎榜席位榜 | `dragon_tiger` `GROUP BY seat_name` | `GET /api/analytics/dragon-tiger` |
| 关联网络图 | `limit_related`（双向） | `GET /api/analytics/stock/[code]` |
| 每日涨跌停趋势 | `market_daily_summary`（day/month/year） | `GET /api/analytics/trend?granularity=day` |
| 年度趋势对比 | `substr(trade_date,1,4)` 聚合 | `GET /api/analytics/trend?granularity=year` |
| 同时期/同月对比 | `substr(trade_date,1,6)` 聚合 | `GET /api/analytics/trend?granularity=month` |
| 与大盘对比 | `market_index_daily` 叠加（同粒度对齐） | `GET /api/analytics/trend?compareMarket=1&index=sh000001` |
| 次日开盘预测校验 | `next_open_prediction` vs `next_open_actual` | 前端回测面板 |
| 个股全貌 | 记录 + 关联 + 席位 | `GET /api/analytics/stock/[code]` |

> 所有 `/api/analytics/*` 均被 `server/middleware/auth.ts` 全局守卫，需登录会话。

## 6. 采集幂等与约定

- 写入一律走 `INSERT ... ON CONFLICT(trade_date, stock_code, limit_type) DO UPDATE`，重跑安全。
- `is_verified = 1` 的记录：`reason_final` / 人工字段**禁止**被任何自动写入覆盖（仅人工/管理员可改）。
- 派生表（`market_daily_summary` 等）由采集/种子脚本按日回填，不依赖前端计算。
- 时间字段统一 `YYYY-MM-DD`，时刻统一 `HH:MM:SS`，避免时区歧义。

## 8. 演进与扩展点

- 增加「涨停时段分布」可再加 `first_limit_time` 分桶分析，无需新表。
- 预测模型上线后，把 `next_open_prediction` 改为模型输出、`next_open_actual` 由 T+1 采集回填，即得回测闭环。
- 关联图若需权重传播，可在 `limit_related.weight` 基础上做图算法，无需改结构。
